## 📰 奈飞开源视频擦除模型VOID：不只删物体，还能重算剩余物体的物理运动

> **分类**: 链上侦探  
> **时间**: 10:41  
> **来源**: [blockbeats](https://www.theblockbeats.info/inclusionid/?target=https%3A%2F%2Ft.me%2FOneMillion_AI)

据 1M AI News 监测，奈飞研究院与保加利亚索菲亚大学 INSAIT 联合开发了 VOID（Video Object and Interaction Deletion），一个能从视频中移除物体并重新模拟剩余场景物理行为的 AI 框架。4 月 3 日以 Apache 2.0 许可证在 Hugging Face 开源，是奈飞研究院首个公开发布的 AI 工具。

传统视频擦除工具擅长填补背景、修正阴影和反射，但遇到物体之间存在物理接触的场景（碰撞、支撑、推动）就会穿帮。VOID 的核心能力是理解物理因果：移除一排多米诺骨牌中间的一块，后续骨牌不会继续倒下；移除跳入泳池的人，水面不会溅起水花；移除持吉他的人，吉他会自然落地。

技术管线分三层：

1. Meta 的 SAM2 做物体分割，谷歌 Gemini 分析场景语义，生成四值「quadmask」，分别标记主体、重叠区、受影响区和背景，告诉模型不只该擦什么，还有哪些东西会因此改变
2. 基于阿里巴巴 CogVideoX-Fun-V1.5-5b-InP（50 亿参数扩散 Transformer）微调的第一阶段推理，生成物理合理的反事实轨迹
3. 可选的第二阶段「光流噪声稳定」，用第一阶段预测的运动初始化时间相关噪声，防止长片段中物体变形

训练数据由两套物理模拟生成：约 1900 组 Kubric 刚体动力学数据和约 4500 组 HUMOTO 人体动捕数据，在 8 块 A100 80GB GPU 上完成训练。25 人偏好测试中，VOID 64.8% 的选择率大幅领先商业工具 Runway 的 18.4%。推理需要 40GB 以上显存（A100 级别），论文尚未经同行评审，奈飞也未宣布将其纳入制作流程。

## 📰 用户用12万条API记录实锤Claude Code缓存缩水，Anthropic称反而更便宜

> **分类**: 链上侦探  
> **时间**: 10:22  
> **来源**: [blockbeats](https://www.theblockbeats.info/inclusionid/?target=https%3A%2F%2Ft.me%2FOneMillion_AI)

据 1M AI News 监测，Claude Code 用户 Sean Swanson 在 GitHub 提交了一份 bug 报告，用硬数据指出 Anthropic 在 3 月初悄悄动了 Claude Code 的缓存机制。简单说，Claude Code 每次对话都会带上大量上下文（已有代码、背景指令等），这些内容会被缓存起来避免重复处理。缓存保留越久，后续对话越便宜；一旦过期，就要重新处理、重新花钱。

Swanson 分析了两台设备上 1 月 11 日至 4 月 11 日共约 12 万条 API 调用记录，发现 2 月 1 日至 3 月 5 日，所有请求的缓存保留时间都是 1 小时；3 月 6 日起，缓存保留时间被改回了 5 分钟，导致缓存创建成本上升 20%-32%。他的 $200/月订阅半年以来从未用光配额，3 月是第一次。

Bun 创始人、现供职于 Anthropic 的 Jarred Sumner 认可了这份分析，但认为改回 5 分钟缓存整体上反而更便宜：很多请求只用一次就不会再访问，5 分钟缓存的写入价格只有 1 小时缓存的一半，一次性请求没必要花双倍价格写一个用不到的长期缓存。Swanson 部分认同这个说法，短平快的子任务确实受益于低写入成本。但他的核心反驳是：Claude Code 最典型的使用场景恰恰是长时间、大上下文的主会话，5 分钟缓存对这类用户的惩罚太大。

Claude Code 创始人 Boris Cherny 则指出了另一个烧配额的原因：付费用户可用 100 万 token 的超大上下文窗口，一旦缓存过期需要重新处理，成本非常高。「离开电脑超过一小时再回来继续旧会话，基本就是全部重新处理。」他透露 Anthropic 正在考虑将默认上下文窗口缩减至 40 万 token，用户仍可手动切回 100 万。目前部分 Pro 用户（$20/月）的配额消耗已严重到五小时内只能发两条消息。也有用户指出缓存代码本身存在 bug，认为在这些 bug 修复之前，争论缓存保留 5 分钟还是 1 小时没有意义。
