## 📰 微软70多个开源库遭Miasma蠕虫投毒，与5月GitHub被搬空案系同伙所为

> **分类**: 链上侦探  
> **时间**: 13:03  
> **来源**: [blockbeats](https://www.theblockbeats.info/inclusionid/?target=https%3A%2F%2Ft.me%2FOneMillion_AI)

据动察 Beating 监测，微软托管在 GitHub 上的 70 多个开源代码仓库因遭遇 Miasma 蠕虫攻击被紧急关停。受感染的仓库主要包括 Azure Functions 主机进程，以及 Durable Task 任务编排框架在 .NET、Java、Go 和 JavaScript 等多语言下的开源版本。

微软这次被投毒，与 5 月中旬 GitHub 内部代码被盗案系出同源。当时，黑客组织 TeamPCP 在微软应用市场上架了带毒的 VS Code 扩展程序，一名 GitHub 员工在短短 11 分钟的上架空窗期内下载中招，导致电脑里的凭证和密钥全被窃取。黑客利用这些凭证绕过安全网，盗走了 GitHub 约 3800 个内部仓库。得手后， TeamPCP 在论坛公开并开源了自复制蠕虫框架 Mini Shai-Hulud。本次入侵微软的 Miasma 蠕虫，正是 Mini Shai-Hulud 的变种升级版。

Miasma 蠕虫的运行机制专门针对 AI 编程场景。黑客利用此前盗取的微软贡献者 Token，向受信任的官方仓库注入恶意代码。开发者只要在 Claude Code、Cursor 或 Gemini CLI 等 AI 助手中打开或分析这些受污染的项目，编程助手在解析配置文件时就会自动触发恶意载荷。蠕虫激活后会在后台扫盘，窃取开发者电脑里的 AWS、GCP 和 Azure 云凭证，以及 SSH 密钥、npm/PyPI 令牌和 Kubernetes 密钥，并利用新到手的凭证寻找下一个 GitHub 仓库进行投毒，实现自动化自我复制。

这已经是微软 Durable Task 开源项目在数周内第二次沦陷（5 月底曾被植入过恶意 Python 依赖包）。针对 6 月初的恶意提交， GitHub 自动防御系统反应极快，在代码提交后的 105 秒内便自动关停了 73 个受感染的仓库，成功阻断了蠕虫扩散。目前，微软已通知少数拉取了受损代码的开发者，开始紧急轮换凭证，并在安全审计后逐步恢复受影响的仓库。安全机构提示，随着供应链攻击演变为针对 AI 智能体工作流的自动化蠕虫，开发者需审慎评估在 AI 助手中直接运行未知仓库的风险。

## 📰 苹果云端模型「AFM Cloud Pro」比肩Gemini，非谷歌制造但托管于谷歌云

> **分类**: 链上侦探  
> **时间**: 12:54  
> **来源**: [blockbeats](https://www.theblockbeats.info/inclusionid/?target=https%3A%2F%2Ft.me%2FOneMillion_AI)

据动察 Beating 监测，苹果在 WWDC 2026 大会后的技术座谈中澄清了与谷歌的合作内幕。内置于操作系统的 Apple Intelligence 使用的并非公版 Google Gemini，而是苹果自研的四款 AFM 系列模型（AFM Core、Core Advanced Cloud、Cloud Image 与 AFM Cloud Pro）。在这些模型中，最先进的云端大模型「AFM Cloud Pro」性能虽可比肩谷歌的 Gemini 前沿模型，但全由苹果自研，谷歌技术仅被作为「磨刀石」：苹果利用 Gemini 的输出结果，对自研模型进行强化学习与蒸馏精炼。

为了以极低成本获取最先进的智能，苹果避开了耗资数百亿美元的服务器军备竞赛，直接在谷歌云（Google Cloud）的英伟达 GPU 上运行自研大模型。这也是苹果首次官方确认私有云计算（Private Cloud Compute）已延伸到第三方云上。为了防范第三方读取用户数据，系统引入了英伟达最新的「模糊机密计算」（ambiguous confidential compute）芯片级技术，确保芯片在完全无法读取服务器内容的状态下进行私有计算。

在系统运行时，苹果通过内置于操作系统的「系统协调器」（System Orchestrator）来解决算力与隐私的动态分配。协调器会实时评估用户的指令需求，当端侧算力不足以应对时，才将任务路由到云端。通过将大模型运行在装有「芯片锁」的谷歌云中，苹果在利用对手算力的同时，维护了自身作为「隐私守护者」的产品定位。

## 📰 小米MiMo推出UltraSpeed推理模式：单节点突破千tokens/s

> **分类**: 链上侦探  
> **时间**: 08:56  
> **来源**: [blockbeats](https://www.theblockbeats.info/inclusionid/?target=https%3A%2F%2Ft.me%2FOneMillion_AI)

据动察 Beating 监测，小米MiMo 团队与 AI 编译优化系统组 TileRT 宣布推出 MiMo-V2.5-Pro-UltraSpeed 推理模式。在单台标准的 8 卡通用 GPU 节点上，成功在 1 万亿参数的混合专家（MoE）模型上实现超过 1,000 tokens/s 的极限生成速度，峰值可达约 1,200 tokens/s。这标志着在无需采用晶圆级集成或纯片上 SRAM 专用芯片等非常规硬件的情况下，仅凭标准通用硬件和模型-系统协同设计首次突破 1T 模型千 token 生成速度。

推理性能突破源于模型架构与系统的协同设计。在模型架构上，MiMo-V2.5-Pro 采用混合滑动窗口注意力（Hybrid SWA），70 层网络中仅 10 层为全局注意力（Full Attention），其余 60 层为窗口大小 128 的局部窗口注意力，将 KVCache 存储需求压低至传统全注意力（Full Attention）架构的 1/7。在量化层面，团队基于 OCP 联盟的 MX 显微缩放格式标准，对 MoE 专家层进行选择性 4-bit 量化，进一步压缩了内存占用并降低了显存带宽压力，同时对核心非专家模块保持 FP8 精度，确保生成质量不降级。

在猜测解码上，DFlash 框架采用轻量化块扩散（Block-Diffusion）模型与非因果注意力掩码（Non-causal Attention Mask），打破了传统猜测解码的逐字自回归串行瓶颈，支持在单次前向传播中直接预测整块 Token 候选，提升了 GPU 计算利用率与验证效率。

作为系统底座的 TileRT 推理引擎则提供了精细匹配的编译器与定制算力内核。引擎核心采用常驻运行（Persistent Execution）模式，使计算流水线常驻 GPU，消除了频繁的算子内核启动开销并杜绝了流水线空泡。

小米MiMo 已在 Hugging Face 开源了包含 FP4 与 DFlash 猜测解码检查点的 1T 模型权重。官方于 6 月 9 日至 6 月 23 日（PDT）启动 UltraSpeed API 限量试用申请。试用期结束后，UltraSpeed API 定价将调整为标准版的 3 倍，并提供近 10 倍的速度提升，网页端聊天界面则限时免费开放。企业与大规模需求可联系 business-mimo@xiaomi.com 。

## 📰 OpenAI研究员Noam Brown倡导引入推理算力曲线，单一跑分已无法衡量前沿大模型

> **分类**: 链上侦探  
> **时间**: 18:55  
> **来源**: [blockbeats](https://www.theblockbeats.info/inclusionid/?target=https%3A%2F%2Ft.me%2FOneMillion_AI)

据 动察 Beating 监测，OpenAI 研究员 Noam Brown 发表观点指出，随着 AI 模型性能的提升，衡量模型好坏的基准测试分数，正逐渐被推理时算力（即模型回答问题时消耗的计算资源）主导。单一的静态分数已经无法体现强模型的真实水平，未来的评估标准需要转向以推理算力或生成 Token 数量为横轴的性能扩展曲线。

Noam Brown 以新模型 GPT-5.5 的测试过程为例，在最初的常规测试中，GPT-5.5 相比 GPT-5.4 优势并不明显。然而，一旦分配了更多的推理算力，GPT-5.5 的表现便迎来爆发式增长。如果限制了运行预算，标准测试就无法反映前沿模型的真实上限。类似的性能扩展表现已被多项外部评估所证实。在 Andrej Karpathy 的智能体自主研究实验，以及英国 AI 安全研究所的恶意网络测试中，随着推理预算的增加，GPT-5.5 与 Mythos 模型的表现持续走高，即使在生成超过 100M 个 Token 后依然没有触及天花板，且越强大的模型在投入更多算力时性能提升越显著。

推理算力的提升也让安全评估变得更加复杂。Noam Brown 警示称，目前的生物或网络安全评测通常没有固定推理预算。在国家级对手为特定任务投入超过 1000 万美元推理预算时，原本看似安全的模型可能跨越危险红线。大模型厂商发布新模型时应主动公开以 Token 数量、算力成本或运行时间为横轴的性能曲线，评测机构也需要将推理预算列为评估的核心变量，在安全评估中通过低算力测试向外推算安全边界。
