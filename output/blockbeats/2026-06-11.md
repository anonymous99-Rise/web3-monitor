普通编程智能体多依赖模型自主记录笔记，常因模型未主动触发而遗忘关键上下文。MiMo Code 引入持久记忆系统，将状态记录外包给独立的子智能体（subagent）。在会话窗口接近上限时，子智能体自动保存状态并重建一份干净的简报，供主智能体无缝衔接。内置的 /dream 命令每 7 天自动运行，由独立智能体读取历史会话与记忆文件，执行合并、去重与路径有效性验证，将分散信息压缩为当前状态以更新全局记忆。

为提升模型与智能体框架的适配度，MiMo Code 专为 MiMo 系列模型设计了专属 Harness 系统。用户按下 Tab 键切换至 Compose 模式，提供基础需求后即可由系统自主执行设计、规划、编码、测试与审查的完整开发闭环。在 SWE-Bench Pro 与 Terminal Bench 2 权威测试中，使用相同底座模型的 MiMo Code 分别取得 62% 和 73% 的成绩，相比 Claude Code 提升了 5 个百分点。

MiMo Code 还内置语音控制功能，支持用户通过口头指令修改输入或执行发送等操控动作。在部署与使用上，macOS 与 Linux 用户可通过 curl 命令一键安装，Windows 用户支持使用 npm 部署。启动后，终端将呈现完全汉化的 TUI 界面，并在右侧常驻状态看板以供随时观察工作进度。

据动察 Beating 监测，人工智能公司 Writer 发表两篇论文指出，大模型虽然能抗住用户的当场反驳，但如果把偏见伪装成用户的「长期偏好」写入记忆，模型就会大范围妥协。原本用来改善体验的记忆功能，反倒成了模型犯错的温床。

研究测试了 Mem0、MemOS 与 Zep 等外置记忆系统。在科学测试中，长期记忆会反复调用存入的错误观点，导致模型错误率较无记忆状态暴增 2 至 4 倍，连能力较强的 GPT-5.2 也不例外。而在创意推荐任务中，只要记忆里存过用户偏好，模型在无关场景下也会频繁重复相同推荐，干扰率高达 87% 以上，导致创意多样性减半。

## 📰 让AI自己改训练代码，Recursive刷新三项算法优化纪录

> **分类**: 链上侦探  
> **时间**: 19:14  
> **来源**: [blockbeats](https://www.theblockbeats.info/inclusionid/?target=https%3A%2F%2Ft.me%2FOneMillion_AI)

据动察 Beating 监测，AI 初创公司 Recursive 公布旗下科研系统的首批实验结果。系统能自动提出想法、编写代码、运行实验并验证，在固定预算训练、NanoGPT 极速训练和 GPU kernel 优化三项基准中均超公开最佳结果。实验表明，在目标明确、反馈快速的任务里，系统已能找到人类漏掉的优化空间。

在限制 5 分钟的 NanoChat Autoresearch 训练中，系统将验证损失 BPB 降至 0.9109，使达到同等损失的训练时间缩短约 23%（提速 1.3 倍）。关键改动是增强短上下文记忆，把二元和三元 token 组合哈希到固定 embedding 表，再通过可学习门控混入 attention value path，以极低开销直接利用局部信息。

在已被社区优化两年多的 NanoGPT Speedrun 中，系统将训练到指定损失的耗时从 79.7 秒压到 77.5 秒。优化手段包括把 FP8 前向计算推进 attention path 提高吞吐，同时改写 fused MLP kernel，只保存平方 ReLU 激活并在反向传播时重算中间变量以减少显存读写。

在 GPU kernel 优化基准 SOL-ExecBench 中，系统在英伟达 B200 上把平均 SOL 分数（达到理论极限占比）从 0.699 提高到 0.754，使与物理极限的差距缩小 18%。生成方案包括把 GRN 缩放吸收到后续线性层权重、把专家路由的 score 和 index 打包成键值做 warp 内规约，以及在 NVFP4 MoE kernel 中用底层 PTX 指令打包 FP4，并在中间计算中保留 FP32 降低误差累积。为防止 AI 钻漏洞刷分，系统引入多级正确性审计以过滤无效提速。
