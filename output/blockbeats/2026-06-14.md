## 📰 里约市政府开源397B大模型，隐式推理让能力增幅接近翻倍

> **分类**: 链上侦探  
> **时间**: 11:03  
> **来源**: [blockbeats](https://www.theblockbeats.info/inclusionid/?target=https%3A%2F%2Ft.me%2FOneMillion_AI)

据动察 Beating 监测，巴西里约市政府旗下市政信息与规划公司 IplanRIO 在 Hugging Face 开源 Rio-3.5-Open-397B。模型基于 Qwen 3.5 397B 后训练，采用 MoE 架构，总参数约 3970 亿，单 Token 激活约 170 亿参数，支持约 100 万 Token 上下文，并以 MIT 协议开放。

模型卡显示，Rio-3.5-Open-397B 集成了 SwiReasoning 推理框架。SwiReasoning 是一种免训练推理方法，会根据信息熵变化，在显式思维链与隐式向量空间推理之间切换。显式推理负责把结论写成自然语言 Token，隐式推理则在隐藏空间中探索多条路径，减少不必要的文字输出。

团队披露的测试显示，Rio-3.5-Open-397B 在开启隐式推理后，SWE-Bench Pro 得分为 58.1，IMOAnswerBench 得分为 89.5。作为对照，Qwen 3.5 397B 原版分别为 50.9 和 80.9，仅后训练且不启用隐式推理时分别为 54.8 和 84.5。也就是说，隐式推理没有让模型绝对性能翻倍，但让相对基座模型的提升幅度接近翻倍。

兼容性是主要限制。Hugging Face 讨论区中，团队成员确认这些公开分数是在启用 SwiReasoning 后取得的。SwiReasoning 需要在推理时输入概率加权的连续「软嵌入」向量，而 llama.cpp 这类只支持离散 Token ID 生成的推理引擎暂时无法完整实现。团队称，不启用隐式推理时模型仍明显强于 Qwen 3.5 397B 原版，但完整能力需要推理框架适配软嵌入输入。

据动察 Beating 监测，大模型落地企业最大的障碍是缺乏内部背景知识（如表结构、工作流或 API 说明）。由于知识散落在不同系统、代码注释或员工脑中，开发人员不得不针对不同 AI 工具重复搭建检索管线。

为此，谷歌发布开放知识格式（OKF）v0.1 规范，正式将 Andrej Karpathy 提出的「LLM-Wiki」模式标准化。规范无需新软件或开发套件，主张将所有内部知识写成直观的 Markdown 文本文件，并随源码一同托管在代码仓库中。

在技术结构上，OKF 知识包由 Markdown 目录树构成。每个文件顶部使用文本标签声明类型、描述和日期，文件间通过超链接建立引用关系；同时配备用于快速预览架构的 index.md 和记录更新历史的 log.md。

此外，规范采用了宽容的解析模型。即便 AI 在自主生成文件时遗漏了字段、写错类型或留下了死链接，系统也不会报错崩溃，确保了极高的容错性。
