> **时间**: 11:44  
> **来源**: [blockbeats](https://www.theblockbeats.info/inclusionid/?target=https%3A%2F%2Ft.me%2FOneMillion_AI)

据动察 Beating 监测，让开发者告别手写代码的 Claude Code 是如何做出来的？Anthropic 官方复盘了这一工具的幕后研发故事。

研发团队曾在 2023 年构建过一款名为 clide 的内部小工具。由于传统大模型上下文窗口的限制，这款工具在处理超出窗口的文件目录时，甚至需要并行启动 100 个 Claude Haiku 模型分头读取，不仅启动极慢，还充斥着繁杂的指令。

2024 年 9 月，刚从 Meta 离职的首席工程师、《Programming TypeScript》作者 Boris Cherny 加入实验室团队。他最初计划以编写一个简单的代码静态检查器（Linter）作为切入点，但在主管的劝阻和鼓励下，他决定放手做件大事，从零开发了一款全新的命令行工具，并将其命名为 Claude CLI。在最早的演示中，这个工具展现出直接操控本地系统基础命令的魔力：它能自动屏幕截图、读取 Apple Music 界面，并准确识别出 Boris 正在听什么歌。

随着 Claude 4 模型能力的跨越式突破，这款原本像玩具一样的工具直接爆发出惊人的迭代速度。由于命令行架构极为轻量，无需维护复杂的网页端，团队几分钟内就能完成热更新。伴随 2025 年 2 月公开测试，Claude CLI 被正式更名为 Claude Code。到了 2025 年底，负责人 Boris Cherny 与家人在沙发闲坐时，直接用对话命令让 Claude Code 一天内自动递交了 88 个代码提交（commit）。他与核心成员 Igor Kofman 均已实现 100% 的代码交由 Claude Code 编写，自己不再亲手写任何一行代码。
