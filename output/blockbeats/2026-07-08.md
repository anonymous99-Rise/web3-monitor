## 📰 告别断连与沙箱重置，Gemini API 托管代理引入后台异步与远程MCP直连

> **分类**: 融资  
> **时间**: 08:25  
> **来源**: [blockbeats](https://www.theblockbeats.info/inclusionid/?target=https%3A%2F%2Ft.me%2FOneMillion_AI)

据动察 Beating 监测，Google 宣布为 Gemini API 托管代理（Managed Agents）引入多项底层基础设施更新，提升智能体在云端运行的稳定性。

托管代理是在 Google 隔离沙箱环境中运行的智能体。此前，开发者在部署生产级应用时面临三大障碍：长任务容易因 HTTP 超时断连；连接私有数据需要自建中转代理；更新授权密钥会重置沙箱，导致已安装的依赖包和 git 仓库丢失。

四项调整直接解决了这些障碍：
1. 异步后台执行：传入 background: true 即可在云端异步运行任务。API 会立刻返回任务 ID，客户端无需保持长连接，可随时轮询状态或重连接收进度。
2. 远程 MCP 服务直连：智能体能直接与远程 Model Context Protocol（MCP）服务器通信，无需中转代理即可安全读取私有数据库或内部接口。
3. 混合函数调用：沙箱工具在服务端运行，自定义本地函数则会将状态标记为 requires_action，交由客户端本地执行特定业务逻辑。
4. 无损刷新网络凭证：开发者在轮换短效 API 密钥或凭证时，可使用 environment_id 直接覆盖配置，且保留云端沙箱内的文件系统、已克隆仓库和已安装的依赖包。

目前托管代理已在 API 免费层开放，开发者可使用 @google/genai 开发工具包直接调用。

以往大模型看图和听音，需要先用独立的「翻译器」（编码器）把图像和音频翻译成大模型能懂的特征。Gemma 4 12B 模型首次实现了视觉与音频双模态的「无编码器」（Encoder-Free）极简一体化。它直接把视觉翻译器砍掉 93%，音频翻译器完全干掉，让原始图像块和音频片段直接投射进大模型脑海中，彻底解决了「外挂翻译器」造成的显存浪费。

在长文本和加速优化上，Gemma 4 同样做了极简设计。它通过 Value=Key 的全局注意力复用，让大模型在处理长文本时「少记一种特征」，直接将全局记忆（KV 缓存）占用减少了 37.5%。为了在手机上更快打字，其轻量级端侧版本（E2B/E4B）的预测加速器还把需要检索的词典范围从 26 万个词缩减到 4096 个，让解码速度飞起来。

不过，目前仅 12B 模型实现了这种完全「音画直入」的极简架构，其余尺寸版本在看图听音时仍需要外挂独立的翻译器。
